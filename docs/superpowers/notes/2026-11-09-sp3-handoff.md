## Recommendations for SP4 (from the reviews)

- Replace `nodes/challenge.py` and `nodes/remediate.py` with gateway agents using the same two-call pattern; keep the artifact kinds `findings` and `responses`; the challenger's context must be built only from lineage (rendered document, validation report, plan, passages) and the sentinel test must prove developer-side state cannot reach it. Extend `--rerun-llm` to both nodes and `LLM_DERIVED_REFS` accordingly.
- The eval harness should measure, per profile: grounding pass rate (the `document_sections` summary already carries `n_flagged_sections` and `n_ungrounded_numbers`), retrieval recall at 5 on `packages/knowledge/tests/golden_questions.yaml` (consider whether indexing the full heading path in every chunk inflates common title words), and cost and latency from `llm_calls`.
- Recorded real responses would make the integration tests exercise real model behaviour; the fake is a scripted stand-in and says so.
- Consider: excluding digit runs that follow a decimal point from the redaction scan (full-precision floats currently force the excerpt rounding); scanning the original column names on the scope call too (today only the document node adds them); checking the cost cap before each retry rather than once per call; a `knowledge_index` summary that names the corpus documents and their hashes for the console.
- The console (SP5) should render `DocumentSection.grounding` per section and the `[A:]`/`[K:]` markers as hovers; `status` already exposes `llm_calls`.
