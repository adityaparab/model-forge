Total SP4 live spend: 11.12 USD.

What the numbers mean. The challenger and the loop work on a real model, and the sign-off policy did what it should: with four high findings still open after two rounds, `approve` was refused and the run was sealed with conditions. Two of the challenger's three measured weaknesses are metric design, not review quality: `defect_precision` matches baseline findings by title, which a live model rewords on every call, so its findings on a mutated document all count as extra; and the `missing_limitation` signature expects category `data` with the limitations section as evidence, while the model raised the proxy issue under methodology and conceptual soundness. The third is a real pre-check gap: `undiscussed_test` treats a test as discussed when it is named anywhere, so removing the sentence that reports it changes nothing on a document that names it elsewhere. The `swapped_number` class was inapplicable on this run because the mutation took the first marker sentence (which carried no number); fixed in the closing commit, so the committed `default` baseline carries `null` for it. The remediation loop did not converge: the Opus developer accepts every finding and rewrites, the Opus reviewer keeps conceptual findings open because a rewrite cannot resolve them, and the second round repeated the first round's cost.

## Recommendations for SP5

- The console should render findings and responses per round (status, severity, verdict, the sections regenerated) and the sign-off summary's `max_open_severity`; `status --json` already exposes the rows.
- Remediation prompt: push the developer to dispute with evidence or to accept as a documented limitation (adding the limitation to the limitations section) rather than accepting and rewriting; and let the re-review close a finding that is accepted as a limitation. On the measured run this is where the second round's 2 USD went without convergence.
- Defect precision: match baseline findings by category and evidence sections (or by `check_key`) rather than title; and widen the `missing_limitation` signature to any category with the limitations or data section in evidence.
- `undiscussed_test`: count a test as discussed only when the sentence that names it also carries a marker into the validation report (or sits in the performance section), so removing the reporting sentence is caught.
- Extend the sentinel isolation test to round 2 (findings, responses and regenerated sections) and plant a sentinel in `state.plan`, so a regression to reading the state's plan would be caught.
- A `ci-cheap` live run to commit `evals/baselines/ci-cheap.json` before `evals.yml` is enabled on a remote; consider a smaller cap for probe runs than the pipeline run's (spec 10.5 inherits it).
- Older runs: `FindingResponse.round` now defaults to 1, so pre-SP4 sealed runs replay; the development database holds migration 0004 and the eval and probe rows of this branch.
