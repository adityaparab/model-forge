## Recommendations for SP2 (from the whole-branch review)

- `fit_calibration` takes arrays; add a `calibrate_split(scores_frame, split, method)` wrapper in core so the MCP server does not re-derive the slicing.
- Let `evaluate_thresholds` accept `benchmark=None` and `sensitivity=None` (tests become `not_applicable`) so a run without a challenger still yields a report.
- Add `predict_model(model: Scorecard | GBMModel, frame)` in core as the deterministic dispatcher behind `score_frame`'s `predict` callable; cache the parsed LightGBM `Booster` in the scoring node (`predict_gbm` re-parses the text per call).
- Make the stepwise methodology self-describing: `Scorecard.fit_method: Literal["single", "stepwise_wrong_sign"]` (and optionally the dropped list) so the build node does not replicate the example's merge of drops into `FeatureSelection`.
- `LoadedDataset` carries a DataFrame; the `dataset_ref` should wrap `registry.load_dataset` plus a Parquet cache keyed by adapter name and seed (Taiwan pseudo-vintages depend on the seed).
- The stability node must scope CSI to the model's features (now a `features=` argument on `stability_tests`), as the example does.
- Conventions to carry: `Scores` is a frame contract (`SCORES_COLUMNS`), not a Pydantic artifact; evidence lists are lists, not joined strings; non-finite floats serialize as the strings "NaN"/"Infinity" (Pydantic reads them back; any non-Pydantic consumer must handle them).
