## What SP2 delivers

`packages/lineage` (`modelforge_lineage`): psycopg 3 `Database`, numbered SQL migrations (`0001_initial`, `0002_tool_calls_seq`), hash-chained append-only `events`, content-addressed atomic `ArtifactStore` with deterministic Parquet, runs and skip-locked `run_queue`, steps/tool-call/artifact rows, approvals with four-eyes and loop bounds, inventory, findings, `verify_run`, structlog configuration, and pytest fixtures with a temporary database.

`packages/mcp` (`modelforge_mcp`): four MCP servers on the MCP Python SDK 2.3 (`data-profiler` 5 tools, `credit-modeling` 6, `validation` 6, `doc-renderer` 3) behind one envelope (`register_tool`: Pydantic request and response, `meta.version`, typed `ToolErrorPayload`, structlog on stderr), database-free, runnable standalone (`uv run modelforge-mcp <server>`), with schema snapshots and per-platform goldens (`modelforge-mcp contracts|goldens`).

`packages/orchestrator` (`modelforge_orchestrator`): settings, `Brief`, `RunState` and the manifest/replay/findings schemas, the sync-over-async stdio MCP client (typed `transport`/`timeout` errors, bounded retries, `--marker` process tracking), the `Step` recorder, the LangGraph graph (`intake, scope, gate_scope, profile, split, features, build, validate, gate_model, document, challenge, remediate, gate_signoff, seal`) with a Postgres checkpointer and an explicit msgpack allowlist, gates as `interrupt()` resumed by approvals, deterministic stub LLM nodes grounded in the run's artifacts, seal with manifest and inventory finalisation, replay runs with `ReplayReport`, the worker, and the Typer CLI (`run, approve, resume, abort, status, worker, migrate, replay, verify`).

Also: `Dockerfile`, Compose `worker`, CI Postgres service and Docker build, `templates/sr11-7-dev-doc`, `examples/briefs/polish-pd.yaml` and `synthetic.yaml`, README sections for the governed run, the MCP servers, Compose and configuration.

## Recommendations for SP3 (from the reviews)

- Replace the four stubs (`nodes/scope.py`, `document.py`, `challenge.py`, `remediate.py`) with gateway calls; keep their artifact kinds (`modeling_plan`, `document_sections`, `findings`, `responses`) so seal, replay and the console contracts hold. The `document` node already renders through the doc-renderer; the grounding post-checks need the citation path grammar in spec 4.5 (list-valued fields select by `split`, `test_id`, `feature`, `grade`).
- Replay: add `--rerun-llm` by making the four stub nodes regenerate instead of copying the original refs (the copy branch is isolated in each node).
- Cost cap and `llm_calls`/`prompts` rows: columns exist; `RunState.cost_usd` is carried; enforcement and `raw_ref` storage are SP3's.
- The validation server's summaries encode non-finite floats as the strings "NaN"/"Infinity"; any consumer that formats numbers must treat strings as "n/a" (the document stub does).
- Consider a run-state transition table owned by lineage (`set_status` currently accepts any transition; the worker and `abort` guard the important ones).
- Consider a `load_any_model` helper in `modelforge_mcp.common` (the `parse_model(store.get(...).decode())` idiom appears three times) and a link from a `CalibrationMap` to the model it was fitted on.
- SP5: a lease or heartbeat for a worker killed mid-run (today the run stays `running` until re-enqueued), a worker healthcheck in Compose, non-root container and digest-pinned images, and the identity header replacing the CLI `--approver` argument.
