## Recommendations for SP6

- The threat-model document should name the three exceptions this branch introduces: the identity header is spoofable (identity, not authentication); `MODELFORGE_TRACE_CONTENT=1` sends prompts and completions to the configured collectors; model-derived HTML is served from the console's origin (mitigated by the renderer's `html: False` and the `Content-Security-Policy: sandbox` header on those responses).
- A worker lease or heartbeat: a run whose worker died stays `running` and its console page shows "pause requested" forever; `abort` stays refused while `running`.
- The global SSE stream's residual gap (a commit in flight below the head when a subscriber connects; duplicates on a global reconnect) is documented; a commit-ordered sequence or an `xmin`-based cursor would close it.
- The console replays a run's whole history on every page open (default start 0); passing `?after=<head>` from the first events query would stop that and the live feed's label could read "Latest events".
- Phoenix trace deep links need Phoenix's own trace ids; the console links to the project today.
- `make demo` reads the Compose project name from `COMPOSE_PROJECT_NAME`; the README should mention it where a second stack is wanted.
- The API's request tracing relies on the instrumentor wrapping `build_middleware_stack`, with the lifespan resetting `app.middleware_stack = None` after instrumenting (verified on Starlette 1.10.0 and `opentelemetry-instrumentation-fastapi` 0.66b2; a test guards it).

## Final whole-branch review and fix wave

The whole-branch review (Fable, 7f5bece..243a8f6) returned "with fixes": no Critical, three Important findings and ten minors. Important: finding evidence markers rendered as unresolved citation chips on the findings tab because the findings endpoint returned raw markers; the worker wrote the parked status and released its queue row in two transactions, so a decision landing between them was refused with 409; a `Last-Event-ID` above a run's head starved the run stream. The controller added its own three findings (three order-dependent api test failures from a structlog configuration leaked by a lineage test; the Replays badge showing the latest replay instead of the reproduced one; by-purpose cost rows without tokens) and triaged the minors: eight went into the wave (JSON artifact bytes served verbatim, `ArtifactNotFound` as 404, `record_failure` after the lineage writes with `_close_span` in a `finally`, resume reading the run `for update`, a migration advisory lock, the gate panel key, `Content-Security-Policy: sandbox` and `nosniff` on model-derived HTML and artifact bodies, the health 503 body naming the type only) and the rest stayed deferred (listed above).

One fix wave (Opus, commit 0d12b77) took all fourteen items. It reported four concerns, each ruled on: `observability.get_logger` now returns structlog's lazy proxy because module-level loggers bound at import ignored `configure_logging` in production as well as in tests (accepted); the worker's `finally` release runs only when no outcome was written, since an unconditional release would delete a resume row enqueued right after the park (accepted); a replay report missing from the store now answers 404 on `GET /runs/{id}` as well as `/replays` (parked, see below); two new console test files keep an 80-column wrap from a stray formatter run (cosmetic). The scoped re-review (Opus, 243a8f6..0d12b77) found all fourteen findings addressed and no new Critical or Important breakage; it verified that `configure_logging` sets `cache_logger_on_first_use=False` so the lazy proxy re-resolves on every call, that a raising outcome transaction still reaches the backstop release, and that the `for update` read does not change the lock order against the worker's claim. Residuals parked with rulings: `_settle` clears the pause flag on the needs_attention path even when the claim never happened (harmless); API `abort` releases the queue row before locking the run while `resume` locks the run before inserting, a narrow deadlock window on a parked run that already has a queue row (pre-existing; SP6 should `transition` first, then `release`); `get_logger`'s return annotation names `FilteringBoundLogger` over a lazy proxy (cosmetic). No second fix wave was run.
